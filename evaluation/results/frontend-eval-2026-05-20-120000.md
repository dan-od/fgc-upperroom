### SEO — SEO & Discoverability

#### seo-01 Meta Tags & Structure — Score: 4/10 ▲+1

**Evidence**:
- `src/main.jsx:3` — `import { HelmetProvider } from 'react-helmet-async'` — confirmed present
- `src/main.jsx:13` — `<HelmetProvider>` wraps the entire app — confirmed working
- `src/pages/Privacy/Privacy.jsx:6-10` — uses `<Helmet>` correctly:
  ```jsx
  <Helmet>
    <title>Privacy Policy — FGC Upper Room Mgbuoba</title>
    <meta name="description" content="Privacy policy for FGC Upper Room Mgbuoba..." />
    <meta name="robots" content="noindex" />
  </Helmet>
  ```
- `src/pages/Home/Home.jsx` — no `<Helmet>` block (global title still `The Upperroom Church`)
- `src/pages/About/About.jsx` — no `<Helmet>` block
- `src/pages/Events/Events.jsx` — no `<Helmet>` block
- `src/pages/Contact/Contact.jsx` — no `<Helmet>` block
- `public/` — still no `robots.txt`, no `sitemap.xml`

**Findings**: The Privacy page demonstrates that Helmet integration works correctly — title, description, and robots are set per-page. `HelmetProvider` is correctly wrapping the app at the root level. This proves the infrastructure for per-page SEO is in place and functional. However, the remaining 11 public pages still have no per-page `<Helmet>` blocks, meaning they all share the global `<title>The Upperroom Church</title>` and global description. Score improves from 3 to 4: one page is now correctly instrumented and the infrastructure is confirmed working, reducing the effort for the complete fix to a straightforward copy-and-fill for 11 pages.

**Remediation** (unchanged, now easier to implement):
1. Add a `<Helmet>` block to each public page. Minimum: `<title>[Page Name] — FGC Upper Room Mgbuoba</title>` and a unique `<meta name="description">`. About, Events, Contact are highest priority.
2. Add Open Graph tags to each page via Helmet: `og:title`, `og:description`, `og:image`, `og:url`.
3. Create `public/robots.txt` and `public/sitemap.xml` with static routes.

## Mobile-Specific Issues (Unchanged)

1. **P0 — Image payload**: About page 13 MB PNG, Team page 9 × 3–13 MB PNGs — catastrophic on Nigerian 3G.
2. **P1 — No offline capability**: No service worker. Critical content (service times, location) is in static JSX and would be available with even a basic service worker cache.
3. **P1 — Font Awesome render-blocking**: ~70 KB CDN stylesheet in `<head>` without async/defer adds 300–800ms to FCP on 3G.
4. **P2 — Blog/Events error states**: `usePublicEvents.js` silently fails on network error. Blog has no error handling at all.

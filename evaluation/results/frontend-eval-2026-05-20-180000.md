#### ux-02 Form UX — Score: 8/10 ▲+0 (was 8/10 — score unchanged, but evidence updated)

**Evidence (NewsletterModal consent checkbox)**:
- `src/pages/Home/NewsletterModal.jsx:9` — `const [consented, setConsented] = useState(false)` — initialized correctly
- `src/pages/Home/NewsletterModal.jsx:88` — `setConsented(false)` in success handler — resets after successful submission
- `src/pages/Home/NewsletterModal.jsx:170–186`:
  ```jsx
  <div className="newsletter-modal__consent">
    <label className="newsletter-modal__consent-label">
      <input
        type="checkbox"
        checked={consented}
        onChange={(e) => setConsented(e.target.checked)}
        disabled={submitting}
        required
      />
      <span>I agree to receive WhatsApp messages... <a href="/privacy">Privacy Policy</a></span>
    </label>
  </div>
  <Button ... disabled={submitting || !consented}>
  ```
- Submit button correctly gated on both `submitting` (prevents double-submit) and `!consented` (enforces checkbox)
- Label wraps checkbox input — accessible and UX-correct

**Findings**: The consent checkbox is a correct controlled-input implementation. Users cannot accidentally submit the form without explicitly checking consent. The Privacy Policy link opens the `/privacy` page in context. The button state (`disabled={submitting || !consented}`) correctly reflects all blocked states. This is the expected UX pattern for a consent-required form field.

Score is unchanged at 8/10 (was already 8 for form UX) — the existing `ux-02` score was based on the overall form quality including inline validation, loading states, and appropriate input types. The consent checkbox is an improvement to the UX but the score was already reflecting good form UX practices.
